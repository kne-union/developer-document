# 流程管理：功能评估与上线结论

- 评估对象：[PR #77](https://github.com/kne-union/developer-document/pull/77) 分支 `workbuddy/flow-autonomous-release`（基线 SHA `7fe4d13321ac36e448b432501bad8539e722fc3f`，再加本轮提交）
- 评估日期：2026-11-12（Asia/Shanghai）
- 方法：对照 PR 描述阅读前后端 / MCP 源码与单测；**未**连生产或用户的 PostgreSQL、**未**跑真实 MCP 会话、**未**做浏览器视觉验收。流程主链路单测仍用内存 stub；`checkToken` / 限流 / 事务回滚 / 跨连接并发在本机隔离的真实 SQLite 上验证。测试全绿 **不等于** 可上线，也不等于 PostgreSQL 多实例已证实。
- 本轮代码（在详情页优化与构建依赖之后）：放行凭证与限流改为数据库实现（无内存 Map、无兼容层）；业务流程编号改为项目雪花 ID 字符串。不涉及合并或生产部署，也未在用户或生产库执行任何 SQL。

## 结论（先看这个）

| 场景 | 结论 |
| --- | --- |
| 共享同一数据库的受控试用（内部） | **有条件可以**，须先完成下文「受控试用最小清单」。凭证与限流已入库，进程重启后未过期、未消费的凭证仍有效。多进程必须为每个 worker 配置互不相同的 `SNOWFLAKE_INSTANCE_ID`（0–4095）。 |
| 正式生产 / 多租户商业上线 | **不可以**。流程表无租户隔离、硬删不级联、`startRun` 缺少归属校验等仍是架构级阻塞；本环境也没有在 PostgreSQL 上实测多实例并发。这些不是本轮补丁能消掉的产品决策。 |

产品方向（AI 自主跑完「需求 → 产品设计 → 开发 → 测试 → 预发布」，人工只保留撤回 / 打回 / 暂停；`confirmationId` 为可选复核）在服务层与 MCP 放行工具里 **已按描述实现，并有单测覆盖主路径**。前端后台仍保留「推进 / 回退 / 强制推进 / 完成」等管理员入口，属于管理覆盖，不是逐步真人预签字闸门，但和「人工只保留撤回 / 打回」的对外口径不完全一致，上线前需要产品确认。

## 2. 本轮详情页改了什么（待视觉验收）

针对「信息层级不清、关键人工状态藏得太深、长文本 / 窄屏 / 空态不理想」做了 **操作型界面的收敛优化**，沿用 Ant Design + BizUnit / components-core，不改品牌、不加新库。

1. **待处理打回意见**出现在标题下方的错误横幅（意见正文 +「AI 不能原样再放行」说明 + 跳到台账），折叠标题带「N 条待处理」徽标，并默认展开操作记录。数据来自详情接口 `openFeedback`。
2. **暂停**（含原因 / 发起方口径）和 **超期** 同样在顶部提示，不再只靠一个 Tag 或红色日期。
3. **阶段条**：当前阶段标签带「（当前）」；回看历史阶段时有信息提示；窄屏可横向滚动。
4. **负责人**后端补 `ownerUser` 关联；停留时长写入页头元信息。
5. **需求说明**空态改为明确空提示，不再是单独一个「-」。
6. **操作记录**：表格展示打回意见正文与处理说明；「查看详情」打开证据引用、放行说明、before / after 快照，避免把 JSON 堆在主表。
7. **对比与可读性**：次要文字对比度提高到约 4.5:1 以上；材料卡片左侧状态条由 3px 改为 1px（避免装饰性粗色边）；进度条去掉渐变。加载 / 接口失败有占位和错误空态。
8. **终态一致性**：已完成或已归档不可再改标题等基础字段（带单测）。这是本 PR 范围内的一致性修补，不是完整的「归档后全面禁改」（交付物写入仍未拦）。

**尚未用真实界面验证。** Impeccable `detect` 对改动文件返回空问题列表，不能代替截图。视觉验收待办见文末。

## 2.1 本机预览网络结论（简要）

box 上 `curl http://127.0.0.1:3050` 与 `curl http://172.30.0.2:3050` 均返回预览服务 HTTP 200。computerUse 使用的 Chrome 打不开这两个地址，这是平台访问控制，不是预览进程故障：

- `127.0.0.1:3050` 在代理旁路名单里，随后被强制策略 `LoopbackNetworkBlockedForUrls=["*"]` 拦住，表现为 `ERR_CONNECTION_REFUSED`（故意不暴露本机服务是否存在）。
- `172.30.0.2:3050` 走出口代理 `127.0.0.1:8791`，被当作「目标解析到本机地址」拒绝（SSRF 防护），页面为 `chrome-error://chromewebdata` / Access denied。

不要关闭 `LoopbackNetworkBlockedForUrls`，不要把 3050 加入旁路或 `LocalNetworkAccessIpAddressSpaceOverrides`，不要为视觉验收搭隧道。视觉验收需要产品支持的预览入口（例如在用户本机打开）；用户 Mac 的 localhost 也不是这个 box。

## 3. 风险分级

### 阻塞正式生产（P0）

| 风险 | 依据 | 为何阻塞 |
| --- | --- | --- |
| 流程模型无 `tenantId`，列表 / 详情不做租户过滤 | 模型与 `list` / `detail` / `releaseList` / `humanFeedback` 均无租户条件；系统本身注册了 `@kne/fastify-tenant` | 若生产按租户隔离数据，管理员或 MCP 可能看到 / 操作全部流程。单租户试用可暂时接受 |
| 硬删不级联 | `remove` 只 `flow.destroy({ force: true })` | 留下交付物、台账、run 等孤儿行，审计与撤回语义被破坏 |
| 本环境未在 PostgreSQL 上做多实例并发实测 | 凭证 / 限流 / 回滚测试跑在隔离的真实 SQLite（WAL）；box 上无可用 PostgreSQL 服务端 | SQLite 锁与 Postgres 行锁、多实例连接池行为不同，不能把本轮 SQLite 并发测试当作生产 PG 的充分证明 |

### 应在试用期跟踪、上生产前处理（P1）

| 风险 | 依据 |
| --- | --- |
| 派单 N+1 | `flow-queue.js` `buildCandidates`：先 `flow.findAll`，再对每个 flow 查交付物 |
| 树查询 `path LIKE '${node.path}%'` | `flow-tree.js` `descendants`；分隔符 / 前缀碰撞未纳入本轮 |
| 多 worker 若共用同一个 `SNOWFLAKE_INSTANCE_ID`（默认 1） | `server/server.js` 把 `SNOWFLAKE_INSTANCE_ID` 传给 `@kne/fastify-sequelize` / `nodejs-snowflake`；取值 0–4095。未配置互异时，主键 `id` 与业务 `code` 都可能碰撞 |
| `startRun` 在创建 run 前 **没有** `assertActor` | `services/flow.js` `startRun`：只 `assertNotPaused`。持有 dev token 的调用者若猜到 / 枚举 `flowId`，可能在他人流程上开 run。幂等命中时还会直接返回他人 `contextSnapshot` |
| 归档后交付物仍可 `deliverableSave` / 提交审核 | 本轮只拦了 `update` 基础字段 |
| 读接口（详情、列表、台账、run）主要靠 `adminAuth`，MCP 读路径需再审 scope | 未在真实 MCP 鉴权链路上复验 |
| 无告警 / 失败重试仪表盘 | 队列有 blocked 排除原因，但没有生产级告警 |
| 后台仍可强制推进、豁免必交项 | 管理覆盖有用，但缺少更强的审计展示与权限细分（任意管理员 vs 流程负责人） |

### 本轮已修复（不再作为阻塞或 P1）

- **放行凭证与限流入库**：`t_flow_check_token` / `t_flow_rate_limit`，跨实例共享同一数据库即可；TTL 可清理，重启后未过期凭证仍有效。设计历史上，这两处最初写在进程内 `Map`（提交 `7e55a34` 注释「同一进程内有效，5 分钟」；`7fe4d13` 补充「多实例部署需外置 Redis / DB」）。仓库里没有更早的设计文档说明「为何先用内存」，本文不臆测动机。原实现没有兼容层需求，本轮直接替换，不保留 Map 或旧 token 格式的 fallback。
- **正式消费与放行写入同一事务**：先无消费校验，正式路径在事务内用 `consumed_at IS NULL` 的原子更新消费；事务回滚后凭证仍可消费。dryRun 不消费。
- **业务编号改为项目雪花 ID**：`generateCode()` 现在是 `String(fastify.sequelize.generateId())`，不再用「当月记录数 + 1」。主键 `id` 本来就是 `@kne/fastify-sequelize` 的雪花（BIGINT，读出为字符串）；业务字段 `code`（`STRING(32)` 唯一）与 `id` 是两套值，都来自同一雪花服务。新编号是十进制数字字符串，没有 `FLOW-YYYYMM-` 前缀，也没有旧编号生成路径。本轮**没有**批量改写或删除历史行（「不需要兼容」不等于获权清理生产数据）。`STRING(32)` 宽度足够，无表结构变更，故无 SQL 更新文件。
- **新表不另附建表 SQL**：按项目约定（「有数据库变更写 sql 更新文件，新加表不用」），新增表由模型 + `sync` 初始化。缺少新表迁移 SQL **不是**阻塞项。已有表结构变更才写入 `server/sql/`。本轮未改已有表结构。
- 限流按 `flowId:userId:自然分钟` 窗口、`INSERT … ON CONFLICT DO UPDATE` 原子递增，超限仍保留计数（increment-then-check）。

### 可接受或已缓解（P2）

- 证据 SSRF 在文件通道有协议、内网、DNS、禁重定向约束，单测覆盖主要拒绝路径。
- 放行与状态写入走同一事务、撤回按快照复原：主路径有单测；凭证消费回滚在隔离 SQLite 上已测。
- `confirmationId` 不再是硬闸门，与产品目标一致。
- 详情页信息架构本轮已加强，待视觉确认。

## 4. 最小上线清单

### 4.1 受控试用（建议的「可以试」门槛）

- [ ] 启动时确认 `sequelize.sync()` 已建出 `t_flow_release`、`t_flow_check_token`、`t_flow_rate_limit` 及 `server/sql/flow-management-index.sql` 中的索引；先在预发库演练，保留库备份。不要在生产库直接试验未备份的 `sync`。
- [ ] 每个后端进程设置互不相同的 `SNOWFLAKE_INSTANCE_ID`（整数 0–4095，默认 1）。多进程共用 1 会有主键 / 业务编号碰撞风险。
- [ ] 试用数据视为可丢；不要混入其他租户的正式业务数据（当前无租户隔离）。
- [ ] 手工闭环至少一遍：AI `check → dryRun → 正式放行` → 后台撤回；再跑一遍打回 → `HUMAN_FEEDBACK_PENDING` → `flow_ack_human_feedback` → 可再次放行；再跑人工暂停 / 恢复。
- [ ] 用真实或脱敏材料打开详情页，完成文末视觉清单（横幅、阶段条、窄屏、空态、台账详情）。
- [ ] 确认 dev token 只发给受控的内部 AI 客户端；不要对公网放开未声明 scope 的高权限 token（当前默认打开放行组）。
- [ ] 硬删只在明确了解「不级联」的前提下使用，优先归档。

### 4.2 正式生产还缺什么（仍阻塞，本轮不修）

- 若产品是多租户：流程及相关表补租户键，并在所有读写（含 MCP、台账、反馈）强制过滤。
- 硬删改为级联或禁止硬删、只归档；归档后全面禁写（含交付物）。
- 给 `startRun` 等 MCP 写入口补归属校验，幂等复用不得泄露他人快照。
- 派单查询下推 SQL。
- 告警（放行失败、租约堆积、打回长期未 ack）、审计导出、权限角色（谁可以强制推进 / 硬删）。
- 在预发 **PostgreSQL** 上做集成测试与多实例并发 / 负载（本轮隔离 SQLite 不能代替）。已有表结构变更继续写 `server/sql/` 更新文件；新表仍按现有建模 + `sync`，不把「缺少新表迁移 SQL」当成欠账。
