# 前端构建依赖说明

记录本次为打通 `craco build` / 本地预览而补齐的依赖与脚本调整。版本按仓库既有声明与上游 peer 选取，不盲目追最新主版本。

## 背景

仓库 `package.json` 原先只声明了 `@craco/craco` `^7.1.0` 和 `@kne/modules-dev` `^2.4.17`（实际安装 2.4.20）。`craco.config.js` 使用 `@kne/modules-dev` 的 `CracoRemoteComponentsPlugin`，该插件 `require("@kne/craco")`，peer 为：

- `@kne/craco` `>=7.0.0`（其自身 devDependency 为 `^7.1.2`）
- `@kne/react-scripts` `>=5.0.0`（`@kne/craco` 要求 `>=5.1.0`）
- `loader-utils` `*`（CSS modules 插件直接 `require("loader-utils")`）

项目未声明这三项，安装后 `npm run build` / `craco build` 会因缺模块失败。另外 CLI 若走 `@craco/craco`，会去解析官方包名 `react-scripts`，而本仓库应使用 `@kne/react-scripts`，同样会失败。

## 本次写入 `package.json` 的版本与原因

| 包 | 声明 | 实际解析 | 原因 |
| --- | --- | --- | --- |
| `@kne/craco` | `^7.1.4` | 7.1.4 | 满足 `@kne/modules-dev` peer `>=7.0.0` 及其 devDep `^7.1.2`；npm 按该范围解析到 7.1.4。构建/启动脚本改为显式调用 `node ./node_modules/@kne/craco/dist/bin/craco.js`，避免 `.bin/craco` 落到上游 `@craco/craco`。原有 `@craco/craco` `^7.1.0` 保留，不擅自删除历史声明。 |
| `@kne/react-scripts` | `^5.1.6` | 5.1.6 | 满足 `@kne/craco` peer `>=5.1.0`。5.x 线最新为 5.1.6，没有 6.x，不跨主版本。 |
| `loader-utils` | `^2.0.4` | 2.0.4 | `@kne/modules-dev` peer `*`，取 CRA 5 线常用的 2.0.4，避免误装 3.x。 |
| `@kne/react-form-antd` | `^4.1.12` | 4.1.12 | `@kne/antd-icon-select@1.0.0` 的 peer 为 `*`。4.1.12 是当前 4.x 最新，peer 为 `antd >=6`、`react >=18`。放在 `dependencies`，因为它是生产依赖的运行时 peer。 |
| `antd` | `^6.7.0` | 6.7.0 | 官方当前 6.x 稳定版（2026-11-12 查询）。peer 为 `react >=18` / `react-dom >=18`，与本仓库 `react ^18.3.1` 兼容，不需要升到 React 19，也不需要 `@ant-design/v5-patch-for-react-19`（仓库里本来就没有）。`@ant-design/icons` 已是 `^6.3.4`，满足 antd 6 要求（解析到 6.3.4）。 |

Docker 镜像（`Dockerfile` 第 7 行 `cd /app_build && npm install`，以及第 9 行 server `--production`）使用**默认** `npm install`，不带 `--legacy-peer-deps` / `--force`。此前把 `@kne/react-form-antd` 写成 `^4.1.8` 且宿主仍是 `antd ^5.29.3` 时，默认安装会把 form 解析到 4.1.12，触发 `ERESOLVE`（peer `antd@>=6` 与已解析的 antd 5 冲突），CI 失败。现已将宿主升到 antd 6，声明与默认安装一致，**不再需要** `--legacy-peer-deps`。

未加入 `@kne/modules-dev` 自身的 devDependency（chai / mocha / microbundle 等），它们不是本应用构建所需。

## 脚本

- `start-frontend`、`build` 中的 `craco` 改为调用 `@kne/craco` 的 bin。
- 新增 `build:compile`：只跑编译，不执行 `deploy` / `deploy-prod`（后两者会改 entry HTML，不属于本次「跑通构建」范围）。

## 已验证的编译命令（本机实测）

```bash
CI=false COMPONENTS_NAME=developer-document MODULES_DEV_PUBLIC_URL=/ \
  node node_modules/@kne/craco/dist/bin/craco.js build
```

结果：exit 0，产出 `build/`。告警为既有 eslint / bundle size / tinycolor2 版本提示，不是本次引入的错误。

## antd 6 升级与 Docker 安装（2026-11-12）

- 官方迁移说明（https://ant.design/docs/react/migration-v6/）：v6 主要是技术升级，多数组件 API 仍兼容；要求 React >= 18、`@ant-design/icons` >= 6、现代浏览器与默认 CSS 变量。列出的旧 API（如 `Alert.message` → `title`、`Modal.destroyOnClose` → `destroyOnHidden`、`Tag bordered={false}` → `variant="filled"`）在 v6 **仍可用**，会在控制台弃用警告，计划于 v7 移除。本轮未做全仓库弃用 API 改写，以免扩大范围；编译已通过，**未做视觉验收**。
- 远程组件：CDN `components-core@0.6.15` 的 devDependency 已是 `antd ^6.6.4`、依赖 React 18；`components-admin@1.1.131` 的 devDependency 已是 `antd ^6.3.3`、React 18。宿主升到 antd 6 是与这两份远程构建对齐，而不是拉开。未把远程默认版本升到 `components-core@0.7.5` / `components-admin@1.1.148`，因为这两版依赖 React 19，超出本轮范围，也未验证。远程模块在 antd 6 宿主下的真实运行时表现 **未在浏览器验证**。
- 干净安装验证（本机 Node v24.22.1 / npm 11.21.1，与 Dockerfile 基础镜像 `node:24` 同主版本；CI 日志中该镜像提示可更新到 npm 12.2.2，本环境无 Docker 守护进程，未能做真实 `docker build`）：
  - 空目录只拷 `package.json` 后默认 `npm install`：exit 0，解析 `antd@6.7.0`、`@kne/react-form-antd@4.1.12`、`@ant-design/icons@6.3.4`、`react@18.3.1`。
  - 空目录只拷 `server/package.json` 后 `npm install --production`：exit 0，无 ERESOLVE。
  - 仍可能看到 `npm warn ERESOLVE overriding peer dependency`，来源是历史声明的 `@craco/craco` 拉入官方 `react-scripts@5.0.1` 的可选 peer `typescript@^3 || ^4`，与树中的 typescript 7 不一致。这是安装警告而非失败，本轮未删除该历史声明，也未用 `--force` 掩盖。
- 仓库 `.gitignore` 忽略 `package-lock.json`，Dockerfile 也只 `COPY package.json`，因此镜像内每次是按声明范围解析。本轮通过把范围改到能默认解析的组合来保证确定性，而不是加入 lockfile 或 legacy 开关。
