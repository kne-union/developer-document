# 前端构建依赖说明

记录本次为打通 `craco build` / 本地预览而补齐的依赖与脚本调整。版本按仓库既有声明与上游 peer 选取，不盲目追最新主版本。

## 背景

仓库 `package.json` 原先只声明了 `@craco/craco` `^7.1.0` 和 `@kne/modules-dev` `^2.4.17`（实际安装 2.4.20）。`craco.config.js` 使用 `@kne/modules-dev` 的 `CracoRemoteComponentsPlugin`，该插件 `require("@kne/craco")`，peer 为：

- `@kne/craco` `>=7.0.0`（其自身 devDependency 为 `^7.1.2`）
- `@kne/react-scripts` `>=5.0.0`（`@kne/craco` 要求 `>=5.1.0`）
- `loader-utils` `*`（CSS modules 插件直接 `require("loader-utils")`）

项目未声明这三项，安装后 `npm run build` / `craco build` 会因缺模块失败。另外 CLI 若走 `@craco/craco`，会去解析官方包名 `react-scripts`，而本仓库应使用 `@kne/react-scripts`，同样会失败。

## 本次写入 `package.json` 的版本与原因

| 包 | 声明 | 实际解析 | 原因 |
| --- | --- | --- | --- |
| `@kne/craco` | `^7.1.4` | 7.1.4 | 满足 `@kne/modules-dev` peer `>=7.0.0` 及其 devDep `^7.1.2`；npm 按该范围解析到 7.1.4。构建/启动脚本改为显式调用 `node ./node_modules/@kne/craco/dist/bin/craco.js`，避免 `.bin/craco` 落到上游 `@craco/craco`。原有 `@craco/craco` `^7.1.0` 保留，不擅自删除历史声明。 |
| `@kne/react-scripts` | `^5.1.6` | 5.1.6 | 满足 `@kne/craco` peer `>=5.1.0`。5.x 线最新为 5.1.6，没有 6.x，不跨主版本。 |
| `loader-utils` | `^2.0.4` | 2.0.4 | `@kne/modules-dev` peer `*`，取 CRA 5 线常用的 2.0.4，避免误装 3.x。 |
| `@kne/react-form-antd` | `^4.1.8` | 4.1.8 | `@kne/antd-icon-select@1.0.0` 的 peer 为 `*`、自身 devDep 为 `^4.0.2`。4.1.8 是仍声明 `antd >=5.x` 的最后一版；4.1.9+ 要求 `antd >=6`，与本仓库 `antd ^5.29.3` 冲突。不装 4.1.12。放在 `dependencies`，因为它是生产依赖的运行时 peer。 |

安装需使用 `--legacy-peer-deps`：`@kne/react-form-antd` 更高版本与 antd 5 的冲突会让默认 npm 安装失败；4.1.8 本身 peer 已兼容 antd 5，但仓库里其他包仍可能报 peer 警告。

未加入 `@kne/modules-dev` 自身的 devDependency（chai / mocha / microbundle 等），它们不是本应用构建所需。

## 脚本

- `start-frontend`、`build` 中的 `craco` 改为调用 `@kne/craco` 的 bin。
- 新增 `build:compile`：只跑编译，不执行 `deploy` / `deploy-prod`（后两者会改 entry HTML，不属于本次「跑通构建」范围）。

## 已验证的编译命令（本机实测）

```bash
CI=false COMPONENTS_NAME=developer-document MODULES_DEV_PUBLIC_URL=/ \
  node node_modules/@kne/craco/dist/bin/craco.js build
```

结果：exit 0，产出 `build/`。告警为既有 eslint / bundle size / tinycolor2 版本提示，不是本次引入的错误。
